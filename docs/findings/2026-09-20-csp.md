# The dashboard's Content-Security-Policy, and what it took to prove it safe

**Date:** 2026-09-20
**Area:** Norma, security, deployment

## What

QualityClouds' Norma raised "Missing Content Security Policy" (HIGH) against `frontend/index.html:3`.
The pass on 2026-09-19 accepted it as unverifiable in the time left. It is now shipped, enforced, as a
response header from the backend, and exercised in a real browser.

The header comes from `content_security_policy()` and the `security_headers` middleware in
`backend/app/main.py`, so **every** response carries it: the dashboard, the landing page, the resident
video page, the crews' room, the built assets, the favicon, the service worker and the API. Not a
`<meta>` tag: a meta tag cannot carry `frame-ancestors`, does not protect the assets, and does not
reach the service worker, which takes its own policy from the headers of its own script.

## The policy

```
default-src 'self';
base-uri 'self';
object-src 'none';
frame-ancestors 'none';
form-action 'self';
script-src 'self';
worker-src 'self' blob:;
style-src 'self';
img-src 'self' data: blob: https://tile.openstreetmap.org;
font-src 'self';
media-src 'self' blob:;
connect-src 'self' https://tile.openstreetmap.org wss: https://*.opentok.com https://*.tokbox.com <HACKFIRE_PUBLIC_URL> <HACKFIRE_CSP_CONNECT…>
```

No `'unsafe-eval'` anywhere, and no `'unsafe-inline'` for scripts; `style-src` gained it on 20 September for the Vonage Video SDK (below). A test asserts that.

| Directive | Why it says what it says |
|---|---|
| `default-src 'self'` | Everything not named below comes from this origin. The backend serves the dashboard and the API together, so "this origin" is the whole app. |
| `script-src 'self'` | Vite emits one module script per page and no inline script (checked in `frontend/dist/index.html` and `about.html`). LiveKit and the Vonage SDK are npm packages bundled into our own assets, not remote script tags. |
| `style-src 'self'` | Vite emits stylesheets, not inline `<style>`. React's `style={{…}}` props are set through the CSSOM (`node.style.*`), which CSP does not govern; only `style` **attributes** in markup would need `'unsafe-inline'`, and the app has none in HTML or in the SVG it inlines (`ui/icons/`, checked by `scripts/check-icons.mjs`). MapLibre sets element styles the same way. Verified: zero violations across every page below. |
| `worker-src 'self' blob:` | MapLibre GL builds its tile worker from a blob URL it creates itself. Without `blob:` the map does not draw at all. |
| `img-src 'self' data: blob: https://tile.openstreetmap.org` | The basemap (`OSM_STYLE` in `ui/TriageMap.tsx`). `data:` for MapLibre's own stylesheet, which draws its controls from `url(data:image/svg+xml,…)`. `blob:` for images the SDKs build in memory. The DGT markers are an `ImageData` from a canvas handed to `addImage`, which needs no URL at all. |
| `connect-src` | `'self'` for the API. `tile.openstreetmap.org` because MapLibre fetches raster tiles rather than using `<img>`, **and** because `public/tile-cache-sw.js` fetches them from inside the service worker, under the policy this same header gives it. `wss:` for the voice call (below). `*.opentok.com`, `*.tokbox.com` for Vonage Video. Plus `HACKFIRE_PUBLIC_URL` and anything in `HACKFIRE_CSP_CONNECT`. |
| `media-src 'self' blob:` | The agent's audio and a resident's video arrive as `MediaStream`s attached through `srcObject`, which CSP does not govern, but both SDKs fall back to blob URLs in places. |
| `object-src 'none'`, `base-uri 'self'`, `frame-ancestors 'none'`, `form-action 'self'` | No plugins, no `<base>` rewriting where a script loads from, no framing the coordinator's screen, no posting a form off-origin. |

### Why `wss:` and not a host

`services/voiceSession.ts` connects to `session.livekit_url`, which SLNG returns **per call**, on whichever
LiveKit deployment it picks. Vonage's signalling server is a per-project subdomain of `tokbox.com`.
Neither host is knowable at build time, so pinning one would break the call in front of the judges.
`wss:` allows secure WebSockets and nothing else; with `script-src 'self'` there is no third-party script
on the page that could abuse it. The honest trade: this directive is broad on purpose, and it is the one
directive to revisit if the app ever grows beyond a hackathon.

## Configuration

`backend/app/config.py`, both in `.env.example`:

- `HACKFIRE_CSP_CONNECT` — comma-separated extra `connect-src` sources. For a `pnpm dev:web` dashboard
  pointed at another backend through `VITE_API_URL`, a Vonage region, or a tile mirror.
- `HACKFIRE_CSP_REPORT_ONLY=1` — send the policy as `Content-Security-Policy-Report-Only` instead.
  The browser reports violations and blocks nothing. The escape hatch if the policy ever gets in the
  way of a live demo; it is **not** how the app ships.

`HACKFIRE_PUBLIC_URL` is added to `connect-src` on its own, so a deployment behind a proxy whose public
name differs from the origin in the address bar still reaches its own API.

## What was verified in a browser

Chromium (Playwright), against `uv run uvicorn app.main:app --port 8123` with
`HACKFIRE_DASHBOARD_DIR=../frontend/dist` — the deployed shape, backend and dashboard on one origin.
Every console message and every failed request was collected.

**Zero `Refused to …` violations. Zero console errors. Zero failed requests** other than
`net::ERR_ABORTED` on tiles MapLibre itself cancels while zooming, which happens without a CSP too.

## What is still unverified

Two things need a live session that the demo machine cannot start on its own, so their directives are
reasoned from the code and the SDKs, not observed:

- **The voice call** (`services/voiceSession.ts`, LiveKit). It needs `SLNG_API_KEY` and a dispatched
  session. `connect-src wss:` covers the room, and `media-src 'self' blob:` the agent's audio, which
  `track.attach()` delivers as a `MediaStream` on `srcObject` — not a URL, so not governed by CSP at
  all. Microphone capture is not a CSP matter (it is Permissions Policy). Low risk.
- **Vonage video** (`services/videoCall.ts`, `@vonage/client-sdk-video`). The hosts in `connect-src`
  were read out of the shipped SDK: `anvil.opentok.com`, `config.opentok.com`, `static*.opentok.com`,
  `hlg.tokbox.com` and the per-project Rumor server, all under the two wildcards. **Not included:**
  `d3opqjmqzxf057.cloudfront.net`, which the SDK only reaches for background blur and noise
  suppression — features this app never turns on. If one is ever enabled, add that host through
  `HACKFIRE_CSP_CONNECT` rather than widening the policy in code.
  The residual risk is that the SDK injects a `<style>` element or a `style=` attribute into the
  markup it builds for a publisher, which `style-src 'self'` would block. If a video call ever comes up
  blank with a `Refused to apply inline style` in the console, the fix is `HACKFIRE_CSP_REPORT_ONLY=1`
  for the demo and `style-src 'self' 'unsafe-inline'` afterwards — not a change to the app.

## What the crews' room needed (20 September, after the first deploy)

The first policy broke Vonage Video. In a browser on the deployed `/crew/<room>` page:

- `Connecting to 'https://video.api.vonage.com/session/…' violates … connect-src`, then
  `OT_CONNECT_FAILED (1006)`: the SDK asks that host for the session before it connects, and it is
  neither `*.opentok.com` nor `*.tokbox.com`. It is now listed in `VONAGE_HOSTS`.
- `Applying inline style violates … style-src 'self'`: the SDK styles the video elements it inserts.
  `style-src` now allows `'unsafe-inline'`. Scripts stay on `'self'`, so this allows styling, not code.
